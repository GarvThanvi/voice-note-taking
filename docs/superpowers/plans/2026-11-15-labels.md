# Labels Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let a user create colored labels, attach several to any note, and filter the note list by label, with chips visible on every tab.

**Architecture:** A `Label` row per user with a `#RRGGBB` color, joined to notes through Prisma's implicit many-to-many. The existing `GET /api/note` gains a `labelId` filter and includes each note's labels; note create/update accept `labelIds`. On the client, `activeFilter` grows a `label:<id>` value, one page-level `useLabels` hook owns the label list, and chips render in both card views.

**Tech Stack:** Express 5, zod v4, Prisma 7 (`prisma-client` generator), React 19, Tailwind v4, `tsx`, Node's built-in test runner (backend), Vitest (frontend, pure helpers only).

**Spec:** `docs/superpowers/specs/2026-11-15-labels-design.md`

## Global Constraints

- Backend is ESM (`"type": "module"`): every relative import ends in `.js`, even from a `.ts` file.
- Prisma 7 generator outputs to `backend/src/generated/prisma` (gitignored). After any schema edit run `npm run build` (that is `prisma generate`) before writing code that uses the new model.
- Database access is currently blocked by the developer machine's router DNS refusing `*.ap-southeast-1.aws.neon.tech`. Task 2 cannot pass until it resolves. Fix by setting the Wi-Fi adapter DNS to `1.1.1.1` / `8.8.8.8`, or run the migration from another network.
- `color` is exactly `#RRGGBB`, matched by `/^#[0-9A-Fa-f]{6}$/`, stored uppercase.
- `name` is trimmed, 1–30 characters, unique per user **case-insensitively**; a collision is 409.
- Every label read and write is scoped `where: { ..., userId: req.userId! }`. Never trust a label id from the client without an ownership check.
- Label routes sit behind `authMiddleware`; only `/health` is public.
- No new runtime dependencies. The only new dev dependency in this plan is `vitest` in `frontend`.
- Runtime hex colors use inline `style`, never Tailwind classes.
- UI components have no DOM test harness in this repo. Component tasks verify with `npx tsc -b` plus the step's manual check. Do not add jsdom or Testing Library in this plan.
- Backend routes are exercised with `curl` against `npm run dev`; capture a JWT once and reuse `$TOKEN`.

## Review Focus

These are the five ways this feature is most likely to hurt a real user, each pinned to the task that owns the fix:

1. **A near-black label (`#111111`) or a pale one (`#FFE066`) on a dark and a light surface** — a chip that is invisible or unreadable makes the user's chosen color look broken. Pinned in Task 6 (luminance tests).
2. **A note mutated through a response path that forgot `labels`** (todo toggle, reorder, any voice action) — the chips silently disappear until refresh. Pinned in Task 4 (verification step), Task 5 (verification step), Task 14 (manual step).
3. **`Work` versus `work`** — must 409, not become two labels. Pinned in Task 3 (curl step).
4. **Deleting the label currently being filtered on** — a blank list with a dead filter. Pinned in Task 14 (manual step).
5. **Creating a note while filtered to a label** — if the label is not pre-assigned the note vanishes after saving. Pinned in Task 14 (manual step).

**Files:**

- Produces: HTTP contract used by Task 7 —
  - `GET /api/label` → `{ success: true, labels: Array<{ id: number; name: string; color: string; noteCount: number }> }`
  - `POST /api/label` `{ name, color }` → 201 `{ success: true, label: Label }`
  - `PUT /api/label/:id` `{ name?, color? }` → `{ success: true, label: Label }`
  - `DELETE /api/label/:id` → `{ success: true, message: string }`
  - failures → `{ success: false, message: string }` with 400 / 404 / 409

- [ ] **Step 1: Implement the router**

`backend/src/routes/label.ts`. Shape to follow — four handlers on a router that calls `router.use(authMiddleware)` first, mirroring `routes/note.ts`:

- A shared `labelInclude`:
  ```ts
  const labelInclude = {
    _count: { select: { notes: { where: { deletedAt: null, archived: false } } } },
  } as const;
  ```
  and a mapper `toLabelDto(label)` returning `{ id, name, color, noteCount: label._count.notes }`.
  If the generated Prisma types reject the filtered `_count`, use plain `_count: { select: { notes: true } }` and note it in the commit message. Counts are decorative; never block the task on them.
- A duplicate check helper:
  ```ts
  const findDuplicate = (userId: number, name: string, excludeId?: number) =>
    prisma.label.findFirst({
      where: { userId, name: { equals: name, mode: "insensitive" }, ...(excludeId !== undefined ? { id: { not: excludeId } } : {}) },
    });
  ```
- `GET /`: `prisma.label.findMany({ where: { userId }, include: labelInclude, orderBy: { name: "asc" } })` → `{ success: true, labels: labels.map(toLabelDto) }`.
- `POST /`: `safeParse` with `labelSchema` → 400 with `result.error.issues[0]?.message`; `findDuplicate` → 409 "A label with that name already exists"; `prisma.label.create({ data: { ...result.data, userId }, include: labelInclude })` → 201 `{ success: true, label: toLabelDto(created) }`.
- `PUT /:id`: reject `NaN` id with 400; `findFirst({ where: { id, userId } })` → 404 "Label not found"; if `name` is present run `findDuplicate(userId, name, id)` → 409; `update` with the parsed fields → `{ success: true, label: toLabelDto(updated) }`.
- `DELETE /:id`: reject `NaN` id with 400; `findFirst({ where: { id, userId } })` → 404; `prisma.label.delete({ where: { id } })`; return `{ success: true, message: "Label deleted" }`. Do not touch notes — the join rows cascade.
- Wrap each handler's body in `try { ... } catch (error) { next(error) }` with `next` in the signature, or let Express 5 forward rejections; the file must not leak a raw 500 without the error middleware seeing it.

const resolveLabelIds = async (userId: number, labelIds: number[]): Promise<number[]> => {
  const unique = [...new Set(labelIds)];

- [ ] **Step 4: Implement the helpers**

Rules that are not negotiable:
- `hexToRgba` accepts `#RRGGBB` (case-insensitive), returns `rgba(r, g, b, alpha)` with integers for the channels and the alpha as given; on anything else returns `rgba(128, 128, 128, <alpha>)`.
- `readableTextColor` converts each channel to the 0–1 sRGB range, linearizes it (`c <= 0.03928 ? c / 12.92 : ((c + 0.055) / 1.055) ** 2.4`), computes `0.2126R + 0.7152G + 0.0722B`, and returns `"#0b0d0e"` above `0.45`, else `"#ffffff"`. Malformed input is treated as mid-grey, yielding `"#ffffff"`.
- `parseLabelFilter` returns the id only for `label:<positive integer>`; everything else is `undefined`.
- `labelFilterValue(id)` returns `` `label:${id}` ``.
- `splitChips` slices at the limit (default `CARD_CHIP_LIMIT`) and reports the remainder count.
